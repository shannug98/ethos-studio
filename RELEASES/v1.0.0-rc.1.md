## 1. Release Summary & Changes

`v1.0.0-rc.1` is the authoritative release candidate for the Ethos Dance Studio platform. It contains the complete workshop ticketing system, payment processing, multi-session scheduling, centralized QuestPDF pass generation with derived HMAC QR tokens, MSG91 transactional WhatsApp notifications, Cloudflare R2 authoritative storage, and strict production security hardening.

### Key Functional & Architectural Deliverables
1. **Cloudflare R2 Authoritative Storage**:
   - `R2TrainerApplicationVideoStorageService` and `R2TrainerGalleryStorageService` upload authoritatively to R2 and return R2 object keys.
   - Local `App_Data` filesystem is strictly designated as an ephemeral duration-probing and local upload cache.
2. **Ticket PDF Centralization**:
   - Refactored `ITicketPdfService` to return `PdfBytes` in `TicketPdfResult`.
   - `WorkshopsController.GetTicketPdf` delegates 100% to `TicketPdfService.GetOrCreateTicketPdfAsync(...)` and streams the resulting bytes, eliminating duplicate layout rendering.
3. **QR Code Security**:
   - QR token fallback strictly resolves `!string.IsNullOrWhiteSpace(rawQrToken) ? rawQrToken : _ticketService.DeriveQrToken(ticket)`.
   - `TicketNumber` is never encoded into the QR code.
4. **WhatsApp Transactional Outbox (Phase D)**:
   - 6-variable payload integration for both booking confirmation and ticket PDF passes.
   - Session-specific date and time resolution for multi-session passes.
   - Safe student name fallback (`StudentProfile.User.FullName`) when `GuestName` is empty.
5. **Security & Production Hardening**:
   - `ProductionSecurityValidator` enforces non-empty production secrets prior to startup.
   - Content Security Policy (CSP) explicitly permits `https://api.ethosdancestudio.com` in `connect-src`.
   - Admin API localhost fallback (`127.0.0.1:5252`) is strictly gated by `import.meta.env?.DEV`.
   - Seed passwords removed from `Phase2SeedService.cs`; required via configuration/User Secrets.
   - Node.js pinned to `22.12.0` via `.nvmrc` and `.node-version`.

## 6. Security Audit Findings

- **Zero Secrets Committed**: Verified no database passwords, JWT keys, Razorpay live secrets, or MSG91 keys exist in JSON or repository.
- **Swagger Security**: UI and JSON schema generation restricted to Development (`app.Environment.IsDevelopment()`).
- **Payment Verification Bypass**: Mock payment bypass code is strictly prohibited outside Development; throws `InvalidOperationException`.
- **MSG91 Test Endpoint Security**: Whitelisted phone check and server-level `Msg91:AllowTestEndpoints` check protect against unauthorized live dispatches.
- **Frontend Localhost Immunity**: `adminApi.js` guarantees `http://127.0.0.1:5252` is excluded when `import.meta.env?.DEV` is false.
- **Content Security Policy**: `public/_headers` restricts `connect-src` to `self`, `https://api.ethosdancestudio.com`, `https://media.ethosdancestudio.com`, `https://*.r2.dev`, and Razorpay.

## 7. Deployment Procedure (Roadmap Alignment)

The deployment of `v1.0.0-rc.1` follows the single-environment PROD-only roadmap:
1. **Clean Test Group**: Delete unused `rg-ethos-test`.
2. **Azure PROD Provisioning**: Create `rg-ethos-prod`, `asp-ethos-prod` (Linux B1), and `ethos-prod-api-app`.
3. **Neon PROD Provisioning**: Create `ethos-prod` project and `ethos-prod-db`.
4. **Cloudflare R2 PROD Provisioning**: Create `ethos-production-media` bucket and scoped API token.
5. **Azure Configuration**: Configure all required environment variables in Azure App Settings (`ConnectionStrings__DefaultConnection`, `Jwt__SecretKey`, `TicketSecurity__SecretKey`, `Razorpay__*`, `CloudflareR2__*`).
6. **Schema Migration**: Execute `dotnet ef database update` against `ethos-prod-db`.
7. **Deploy Backend**: Deploy `v1.0.0-rc.1` Release artifact to `ethos-prod-api-app`.
8. **Deploy Frontend**: Deploy React app to Netlify with `VITE_API_BASE_URL=https://api.ethosdancestudio.com`.
9. **DNS Bindings**: Configure `api.ethosdancestudio.com` and `media.ethosdancestudio.com`.
